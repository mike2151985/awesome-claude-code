# סוכני Claude Code — אגף ההנדסה, עיריית כפר יונה

חבילת סוכנים (subagents) של Claude Code המדמה את המבנה הארגוני של אגף ההנדסה
בעיריית כפר יונה: סוכן-על אחד ו-12 סוכנים מומחים, הנשענים כולם על בסיס ידע משותף
וקבוע.

## מבנה החבילה

```
kfar-yona-engineering-agents/
├── README.md
├── CLAUDE.md
└── .claude/
    ├── agents/
    │   ├── handasa-chief.md                 # סוכן-על — שער כניסה ומתאם
    │   ├── handasa-planning.md              # תכנון ותוכניות אב
    │   ├── handasa-licensing.md             # רישוי והיתרים (כולל חפירה והתארגנות אתר)
    │   ├── handasa-infrastructure.md        # תשתיות ופיתוח
    │   ├── handasa-education-buildings.md   # בנייה למוסדות חינוך וציבור
    │   ├── handasa-architect.md             # אדריכל
    │   ├── handasa-landscape-architect.md   # אדריכל נוף
    │   ├── handasa-accessibility-traffic.md # נגישות ותנועה (ועדת תנועה ונגישות)
    │   ├── handasa-gis.md                   # GIS ומידע הנדסי
    │   ├── handasa-assets.md                # ניהול נכסים
    │   ├── handasa-estimates.md             # אומדנים ופרויקטים
    │   ├── handasa-knowledge-regulation.md  # ידע, רגולציה והכשרה
    │   └── handasa-grants.md                # קולות קוראים ותמיכות
    └── knowledge/
        └── kfar-yona-baseline.md            # בסיס הידע הקבוע המשותף לכל הסוכנים
```

## התקנה / שימוש

**אופציה א' — פרויקט ייעודי (מומלץ):** פתחו את תיקיית `kfar-yona-engineering-agents`
כפרויקט Claude Code בפני עצמו (יש בה כבר `.claude/agents` ו-`.claude/knowledge`).
הסוכנים ובסיס הידע ייטענו אוטומטית.

**אופציה ב' — שילוב בפרויקט קיים:** העתיקו את `.claude/agents/*.md` ואת
`.claude/knowledge/kfar-yona-baseline.md` לתוך `.claude/agents/` ו-`.claude/knowledge/`
של הפרויקט שלכם.

**אופציה ג' — זמינות גלובלית בכל הפרויקטים:** העתיקו את קובצי `.claude/agents/*.md`
אל `~/.claude/agents/`, ואת `kfar-yona-baseline.md` למיקום קבוע וציינו את הנתיב
המלא בראש כל קובץ סוכן (כברירת מחדל הקבצים מפנים לנתיב היחסי
`.claude/knowledge/kfar-yona-baseline.md`).

לאחר ההתקנה, ניתן לפנות ישירות לסוכן-העל ("תשאלו את סוכן-העל של אגף ההנדסה על...")
או ל-Claude Code לתת לו לבחור אוטומטית את הסוכן המתאים לפי תיאור הפנייה.

## חשוב — לפני שימוש בפועל

בסיס הידע (`kfar-yona-baseline.md`) כולל אך ורק את העובדות שנמסרו במפורש (מעמד
עירייה משנת 2014, מדד סוציו-אקונומי 7/10, קיום אתר עירייה/אתר הנדסי בקומפלוט/מערכת
GIS, ועדת תנועה ונגישות, הנחיות מרחביות, היתרי חפירה, רישוי, תיאום תחבורה ציבורית).
כל שדה המסומן `[להשלמה]` — קישורים, טלפונים, שמות ועדות מדויקים — **טרם אומת** ויש
להשלימו בנתונים רשמיים לפני הפצה או הסתמכות מבצעית. הסוכנים מתוכננים באופן מכוון
שלא להמציא עובדות, קישורים או פרטי קשר שאינם מתועדים.

## עקרון העבודה

1. **סוכן-העל (`handasa-chief`)** הוא שער הכניסה: הוא מסווג את הפנייה, מפנה
   לסוכנים המומחים הרלוונטיים, ומסנתז תשובה אחודה לפניות רב-תחומיות (למשל הקמת
   מוסד חינוך חדש הנוגעת בו-זמנית לתכנון, רישוי, בינוי, אדריכלות, נוף, נגישות,
   GIS, אומדנים, ולעיתים מימון חיצוני).
2. **כל סוכן מומחה** מוגדר עם תחום אחריות ברור, גבולות מפורשים ("מתי להפנות לסוכן
   אחר"), ועקרונות מענה המבטיחים שהוא לא ימציא נתונים רגולטוריים/כספיים/כתובות.
3. **`handasa-grants`** (קולות קוראים ותמיכות) מתוכנן להשתלב עם סקיל/כלי קולות
   קוראים קיים בפרויקט אם קיים כזה, ולא לשכפל אותו.

## התאמה אישית

כדי להתאים את החבילה למציאות המדויקת באגף:

- מלאו את כל השדות המסומנים `[להשלמה]` בקובץ `kfar-yona-baseline.md`.
- הוסיפו סעיף "מקורות מידע רשמיים" עם קישורים מאומתים (אתר העירייה, קומפלוט, GIS).
- במידת הצורך, פצלו/מזגו סוכנים בהתאם למבנה הארגוני בפועל של האגף.
